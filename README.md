# Lexis

Локальное офлайн-приложение — личный трекер: английские слова, дни, привычки, дела с фокус-сессиями и спорт.
Go + Svelte 5 + PostgreSQL, всё в Docker. Работает на http://localhost:8090.

## Разделы

Сверху — разделы, слева — их подразделы. Адрес страницы живёт в `#/раздел/подраздел` (закладки и «назад» работают).

| Раздел | Что внутри |
|---|---|
| **Английский** | Новые (ввод слов) · Группы (дерево до 3 уровней: перетаскивание, «Переместить в…», новая группа-папка) · Тренировка (интервальные повторения, 5 уровней; группа — вместе с подгруппами) · Грамматика английского (чтение правил по темам) · Статистика · Настройки (лимит новых слов, импорт/экспорт слов) |
| **День** | День (оценка 1–10, дофаминовая шкала из 7 квадратиков, «что классного сделал», рассказ) · Календарь месяца · Неделя (анализ «о чём → вывод» + сводка) · Статистика (графики оценки и дофамина, выполнение привычек) |
| **Привычки** | Отметки за день · Календарь (неделя/месяц, цели полосами) · Цели на период · Наблюдения и выводы · Мои привычки |
| **Мечты** | Список желаний: категории, статусы, заметки, даты, связь с большим делом · Таймлайн: цели на год и месяц, горизонт 10 лет и добавление следующих лет |
| **Учебные карточки** | Дерево групп и подгрупп · Markdown и формулы на обеих сторонах · Пять типов карточек · Пакетный ввод с предпросмотром · Подборки по баллам, два направления и автоматический повтор ошибок · Статистика знаний, слабые карточки, график по дням и календарь активности |
| **Игра** | Распорядок (шкала дня: дело — в любое время, наложил на другое — меняются местами; топ-5 дел на день по дедлайну, важности и объёму; «не доделал») · Задачи (доска со своими колонками, дела с объёмом в блоках по 30 мин, важностью, дедлайном и типом; шаги и граф дела) · Большие дела (интерактивный граф цели, этапов и дел-листьев; зависимости, прогресс и следующие действия) · Фокус (ритуал настройки → работа ⇄ перерывы → итог, отвлечения) · Награды (очки за работу, свой магазин) · Статистика · Настройки (шкала дня, лимит, ритуал, колонки, типы) |
| **Спорт** | Тренировки (неделя; упражнение — «подходы × повторы × вес», подсказки и значения «как в прошлый раз»; данные с часов — минуты и ккал; итоги недели) · Еда (что съел + ккал за день) · Упражнения (справочник, график прогресса) · Статистика (7 / 30 дней: сожжено и съедено, тоннаж, средние) |
| **⚙** (справа в шапке) | Общие (язык) · Данные (полный бэкап, восстановление, «Очистить всё») |

Напоминания — только внутри приложения: после 18:00 на «Дне» точка, если день не оценён; на «Привычках» — сколько позитивных привычек сегодня не отмечено.
Идёт фокус-сессия — в шапке плашка с таймером (видна из любого раздела, клик — на «Фокус»). Таймеры считаются от отметок сервера: перезагрузка страницы ничего не сбивает.

### «Игра» в двух словах

- **Очки:** +1 за каждые полные 30 минут чистой работы в фокусе (без настройки и перерывов). Тратятся в «Наградах»; покупку можно записать в дофаминовую шкалу дня.
- **Перерывы:** каждые 30 минут работы копят 5 минут перерыва; взять больше можно — перерасход подсвечивается.
- **Шаги:** дело можно разбить на шаги (у шагов — свои шаги). На доске и в плане видны только шаги; дело выполнено, когда выполнены все шаги.
- **Достижения:** 10 / 50 / 200 дел и 10 / 50 / 200 часов в фокусе — в «Игре → Статистика».

### Мечты и большие дела

Новое желание создаётся кнопкой в шапке; исполнение — чекбоксом, остальные действия — в меню «⋯».
Желание можно связать с существующим большим делом в форме правки или создать для него новую пустую доску.
Шаг `A → B` ждёт завершения B; зависимости этапа блокируют и его подзадачи. Родители завершаются по детям.
Прогресс делится поровну между корневыми этапами, затем рекурсивно между детьми — дробление одной ветки не увеличивает её вес.
На графе можно выбирать узлы, добавлять подзадачи через «+», отмечать дела и связывать их зависимостями; черновик шага виден сразу. Масштаб меняется кнопками, фон можно двигать.
Перенос и порядок — в форме шага (родитель и место с 0), без перетаскивания. Удаление категории сохраняет желания;
удаление проекта сохраняет желания без ссылки. Старые бэкапы не трогают новые разделы.

Полная спецификация — [docs/SPEC.md](docs/SPEC.md).

## Таймлайн и учебные карточки

**Мечты → Таймлайн:** шкала от серверного текущего года на десять лет включительно (например, 2026–2035).
«Добавить следующий год» расширяет шкалу и сохраняет новый год. Годовые цели видны отдельно; выбор месяца открывает его план.
В форме цели можно изменить год и месяц или связать её с мечтой. Название, статус и большое дело связанной мечты
показываются из списка мечт; заметка и период принадлежат цели. Удаление цели сохраняет мечту, удаление мечты сохраняет
цель без связи, с названием, сохранённым при последнем выборе связи. Самостоятельные цели не добавляются в список мечт.

**Учебные карточки → Материалы:** создай группу «Матстат» и подгруппы (до трёх уровней), выбери группу и добавляй карточки
по одной или пакетно. Карточки можно редактировать, перемещать в другую группу и удалять. Пустую группу можно удалить;
из непустой сначала нужно перенести карточки и подгруппы. Карточки родителя включают всё его поддерево.

Пакетный формат (разделители — отдельные строки с начала строки):

```text
[тип: определение]
Норма вектора $x$
---
$$\lVert x \rVert = \sqrt{\sum_i x_i^2}$$

[тип: теорема]
Закон больших чисел
---
При подходящих условиях $\overline{X}_n \to \mathbb{E}X$.
```

Типы: `определение / теорема / замечание / свойство / лемма`; также `[type: definition|theorem|remark|property|lemma]`.
Первая строка `---` вне блока кода или формулы разделяет стороны; следующие `---` в ответе — обычный Markdown.
Буквальный разделитель на лицевой стороне: `\---`; буквальный маркер типа: `\[тип: теорема]`.
В ограждённых блоках кода (три и более обратных кавычки или тильды) маркеры не разбираются.
Для многострочных формул в пакетном вводе ставь `$$` или `\[` / `\]` на отдельных строках.
`||` остаётся обычным текстом. Превью показывает номер записи и строку ошибки; сохранить пакет можно после исправления ошибок.

Поддерживаются заголовки, выделение, списки, таблицы, ссылки, изображения, код и переносы строк.
Формулы: `$…$`, `$$…$$`, `\(…\)`, `\[…\]` — синтаксис KaTeX, не полный LaTeX (пакеты LaTeX и `\bbox` не поддерживаются;
используй `\boxed`). HTML показывается текстом, результат проходит санитарную обработку, доверенные TeX-команды отключены.
Ошибочные формулы остаются видимыми красным. Длинные формулы и код прокручиваются. Библиотеки и шрифты локальные;
изображения по внешним URL требуют сети.

Тренировка: выбери группу (с подгруппами) или отдельные карточки, направление и число карточек в подборке (по умолчанию 10).
Сервер берёт минимальные баллы; при равенстве — давно не повторявшиеся карточки, затем по id.
Новая карточка имеет 0 баллов. Каждый сохранённый ответ «Вспомнил» даёт +1, «Не вспомнил» — −1, включая повторы.
Ошибка возвращается через три оставшихся вопроса; если вопросов меньше — в конец, если карточка одна — сразу.
Карточка закрывается только правильным ответом; прогресс — число закрытых карточек исходной подборки.
В обратном направлении тип скрыт до раскрытия. После завершения «Следующая подборка» выбирает новый набор по текущим баллам.
Позиция в очереди живёт до выхода; все оценённые ответы сохраняются, английские уровни не меняются.

**Учебные карточки → Статистика:** периоды 7/30/90/365 дней для активности, число оценённых показов,
доля «вспомнил», активные дни, лучшая серия, график по дням и календарь активности с выбором даты.
Отдельно — знания текущей библиотеки за всё время: не разобрано (нет ответов), нужно отработать (балл < 0),
закрепление (0–4), уверенно (от 5). Есть десять самых слабых разобранных карточек с баллами и кнопка отработки
десяти минимальных баллов всей библиотеки (новые карточки тоже учитываются).
Это самооценка, не автоматическая проверка знаний. Незаконченные тренировки и повторные ответы входят в статистику.
Баллы вычисляются из сохранённой истории и восстанавливаются из бэкапов v6 и новее.
История начинается с добавления её сохранения; более ранние ответы не восстанавливаются.
Клавиши: Enter / пробел — раскрыть, 1 — вспомнил (+1), 2 — не вспомнил (−1).

- Docker Desktop

## Запуск и управление

Все команды — из корня проекта.

| Команда | Что делает |
|---|---|
| `python3 run.py` | То же, что `up`: поднять контейнеры и дождаться готовности |
| `python3 run.py up --build` | Пересобрать образ (после изменений в коде) и поднять |
| `python3 run.py up --open` | Поднять и открыть в браузере |
| `python3 run.py down` | Остановить контейнеры (данные сохраняются) |
| `python3 run.py restart` | Перезапустить |
| `python3 run.py logs` | Логи всех контейнеров (follow) |
| `python3 run.py logs app` / `logs db` | Логи приложения / базы |
| `python3 run.py status` | Состояние контейнеров и API |

Docker Desktop не запущен — `run.py` запустит его сам. При первом запуске `.env` создаётся из `.env.example`.

## Данные

- База лежит в Docker-volume `lexis_pgdata`: `down`, `restart` и `up --build` её **не трогают**.
- Удаляет данные только `docker compose down -v` или удаление volume вручную — не делай этого без бэкапа.
- Бэкап: **⚙ → Данные → Скачать полный бэкап (JSON)** — всё: слова и дерево групп, дни, недели, привычки, игра, спорт, мечты, таймлайн, большие дела, учебные карточки, грамматика, история ответов и настройки (бэкап v7).
  Восстановление: **⚙ → Данные → Восстановить** — заменяет разделы, которые есть в файле (старый бэкап без какого-то раздела его не тронет).
  **Перед обновлением приложения** (`up --build` после изменений с новыми миграциями) — сначала скачай бэкап.
- Очистка: **Английский → Настройки → Очистить английский** (остальные разделы остаются) или **⚙ → Данные → Очистить всё**. Настройки остаются в обоих случаях.
- В английском незавершённая тренировка (закрыл страницу посреди сессии) в статистику не попадает; уровни уже отвеченных слов сохраняются.
- Дни, привычки, тренировки и еда записываются за сегодня и прошлые даты, в будущее — нельзя. Распорядок дня — наоборот: сегодня и вперёд, прошлые дни только для просмотра. «Сегодня» — по `TZ` из `.env`.

## Формат ввода слов

Одна строка — одна карточка, **Английский → Новые**:

```
слово || перевод || пример1 <> пример2 || #группа1 #группа2
```

```
apple || яблоко || I eat an [apple] every day || #еда
go_went_gone || идти || I [go] home <> I [went] home <> I have [gone] home || #глаголы
by bus || на автобусе || I go to work [by bus] || #фразы
```

- Примеры и группы необязательны: `apple || яблоко` — уже карточка.
- Несколько примеров — через `<>`, выделяемое слово — в `[скобках]`.
- Три формы глагола — через `_`; дефис — часть слова (`well-known`).
- Группы — с `#` или без, через пробел или запятую. Вложенная группа — через `/`: `#путешествия/аэропорт` (недостающие группы создадутся, слово попадёт в последнюю). Если группа из пути уже лежит в другом месте, строка вернётся с ошибкой — её не переносим молча.
- Пустые строки и строки с `//` пропускаются. Повтор того же слова с тем же переводом не создаёт дубль, а добавляет примеры и группы.

Импорт файлом (**Английский → Настройки → Импорт**): CSV с колонками `term,translation,example,tags` или JSON `[{"term","translation","example","tags"}]`.

## Тренировка слов

Перед началом выбери направление **английский → русский** или **русский → английский**. На лицевой стороне видно
английское слово (или три формы глагола) либо его перевод. Поле ответа готово к вводу сразу. Enter переворачивает
карточку и открывает слово, его примеры и перевод. Дальше выбери «Знаю», «Затрудняюсь» или «Не знаю».

«Английский → Группы» → открой группу → **«Выбрать слова»** рядом с «Тренировать».
Отметь слова (или выбери все), затем **«Тренировать выбранные»**. В диалоге выбери направление и обычную или свободную тренировку.
Свободная тренировка берёт все отмеченные слова без изменения уровней; обычная — новые и на сегодня с текущим лимитом новых слов.
Выборка временная: очищается после запуска, не создаёт списка и не добавляется в бэкап.

## Грамматика английского

В **Английский → Грамматика английского** создай тему, затем добавь правило. Укажи название и объяснение.
Можно добавить формулу, несколько примеров с переводами и пары с типичными ошибками. Объяснение поддерживает Markdown.
Темы можно вкладывать друг в друга, а правила переносить между темами через редактор.

**«Пакетный ввод»** добавляет сразу несколько правил в выбранную тему. В диалоге есть шаблон и предпросмотр.
Для каждого правила нужны заголовок и объяснение. Формула, примеры и ошибки добавляются отдельными строками по желанию.

```text
[тип: правило]
Should + verb
---
Используется для совета.
[формула] Subject + should + base verb
[пример] You should study. || Тебе следует заниматься.
[ошибка] You should to study. || You should study.

[тип: правило]
Although
---
Вводит уступку: хотя, несмотря на то что.
```

**«Читать правила»** открывает правила выбранной темы и её подтем по порядку. Нажми на название в списке, чтобы начать с него.
В читалке работают кнопки навигации и стрелки ← / →. Правила входят в полный JSON-бэкап v7.

## Разработка

### Бэкенд (`backend/`)

```bash
cd backend
go build ./...
go vet ./...
go test ./... -race          # unit-тесты, без БД
sqlc generate                # после изменений в queries/*.sql или migrations/
```

Интеграционные тесты — на отдельной временной базе (порт 5444; тесты сбрасывают схему):

```bash
docker run --rm -d --name lexis-testdb -p 127.0.0.1:5444:5432 \
  -e POSTGRES_USER=lexis -e POSTGRES_PASSWORD=lexis -e POSTGRES_DB=lexis_test postgres:17-alpine
LEXIS_TEST_DSN='postgres://lexis:lexis@127.0.0.1:5444/lexis_test?sslmode=disable' \
  go test -tags integration -p 1 ./... -race
docker stop lexis-testdb
```

`-p 1` обязателен: все пакеты используют одну тестовую базу.

### Фронтенд (`frontend/`)

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173, /api проксируется на бэкенд (:8090)
npm run check    # svelte-check (типы, a11y; предупреждения = ошибки)
npm test         # vitest — чистая логика
npm run build    # сборка в dist/
```

Бэкенд на другом адресе — `LEXIS_API_URL=http://127.0.0.1:XXXX npm run dev`.
Vite слушает `localhost` (на macOS это IPv6) — открывай `localhost:5173`, а не `127.0.0.1:5173`.

### Отладка бэкенда в VS Code

1. В `docker-compose.yml` раскомментируй `ports` у `db` (`127.0.0.1:5436:5432`).
2. `docker compose up -d db`
3. F5 — конфигурация «lexis server» (сервер на `:8090`, база на `5436`).
4. Фронт — `cd frontend && npm run dev`.

Контейнер `app` при этом должен быть остановлен (`python3 run.py down` и затем `docker compose up -d db`), иначе порт 8090 занят.

### Сервер без Docker

```bash
cd backend
LEXIS_HTTP_ADDR=:8090 \
LEXIS_DB_DSN='postgres://lexis:lexis@127.0.0.1:5436/lexis?sslmode=disable' \
LEXIS_TZ=Europe/Moscow \
go run ./cmd/server
```

`lexis healthcheck` — проверка `/healthz` (exit 0/1), её использует healthcheck контейнера.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| `run.py up` ждёт и падает по таймауту | `python3 run.py logs app` — обычно ошибка подключения к БД или занятый порт |
| Порт 8090 занят | Поменяй `LEXIS_PORT` в `.env` и перезапусти |
| На странице «frontend is not built» | Бинарник собран без фронта — `python3 run.py up --build` |
| В браузере «Сервер недоступен» при `npm run dev` | Бэкенд не запущен или не на :8090 |
